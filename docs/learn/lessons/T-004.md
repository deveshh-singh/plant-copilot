# T-004 — C-MAPSS parse and silver transforms: what you just built

## In plain words
NASA's engine files are rows of 26 bare numbers. This card turns them into tables a
person (or the Text2SQL agent) can read: named sensors with units, one key per engine,
and the answer the prediction model will learn, the RUL at every cycle.

## The idea behind it
**Bronze and silver** (D-008): bronze keeps the file as it was (so we can always go
back); silver is cleaned and renamed for use. Like keeping the original receipt and
also typing it into a spreadsheet.
The RUL uses a **window function**: for each row, look at all rows of the same engine
(the "window") and take the biggest cycle, without collapsing rows the way `groupBy`
does. Train engines run to failure, so RUL = last cycle − this cycle. Test engines stop
early, so we add the true RUL NASA gives in `RUL_FD00x.txt`.
Why number the RUL lines ourselves? Spark may shuffle rows, so "the 3rd row" is not
safe; `lines_frame` writes the line number down before Spark ever sees the file.

## Where it lives
```python
last_cycle = F.max("cycle").over(Window.partitionBy(*KEY))  # ← biggest cycle of this engine
remaining = F.when(F.col("split") == "train", last_cycle - F.col("cycle")).otherwise(
    F.col("true_rul") + last_cycle - F.col("cycle")  # ← test: add NASA's true RUL
)
return bronze.join(_test_rul(rul), KEY, "left").select(  # ← attach true RUL to test rows
    "dataset", "split", _engine_id().alias("engine_id"), "unit", "cycle",
    *OP_SETTINGS,
    *[F.col(raw).alias(name) for raw, name, _, _ in SENSORS],  # ← s2 becomes t24, ...
    remaining.cast("int").alias("rul"),
)
```
