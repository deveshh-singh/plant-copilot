The repo can now deploy itself to the Databricks workspace with one command, and a small
setup job created the two schemas and the `raw` volume the data pipeline needs. The

## For STATE's gotchas
- Workspace host: `https://dbc-8b90102c-1331.cloud.databricks.com` (workspace id in URLs: `o=7474648839274516`).
- Serverless: notebook tasks take no `environment_key`; the run used the workspace's default serverless environment (Spark 4.2.0). Local pyspark is pinned `>=4.0,<4.1`.
- `print()` output of a notebook job is not returned by `get-run-output`; use `dbutils.notebook.exit("...")` for evidence.
- Development mode prefixes the job name: `[dev deveshh_singh91] plant-copilot-setup`.
- No Free Edition limit hit (one run ≈ 50 s including serverless start).

## Deviations
- Schemas and volume are created by the setup notebook, not bundle `schemas`/`volumes` resources: in `mode: development` the bundle would prefix their names (`dev_<user>_plant_bronze`), which breaks the fixed names in D-008 and `fetch_cmapss.py`.
- Added `sync.exclude` for `.claude/**`, `work/**`, `docs/**` to `databricks.yml` (first deploy uploaded 87 files; now only code).
- Added `dbutils.notebook.exit(summary)` to the notebook so the evidence is readable from the CLI.
- The host is written in `databricks.yml`; it is not a secret and the profile must match it.
