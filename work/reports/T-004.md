## In plain words
The project can now turn NASA's engine text files into clean tables, in code that is
tested on the Mac without Databricks. Each sensor gets the engineer's name from the
paper (`t24`, `nf`, `ps30` …) with a plain description and unit, and every row knows
how many cycles the engine had left before failure (RUL). T-005 only has to read the
files, call these functions and write the tables.

## Deviations
- **`lines_frame(spark, source_file, text)` added**, and `parse_rul` needs a `line_no`
  column besides `source_file, value`. This is how line order is kept: the reader numbers
  lines in Python (`enumerate`) before Spark sees them. Serverless has no RDD API, so
  `zipWithIndex` was not an option. T-005 should read each file's text (plain `open()`
  on `/Volumes/...`) and call `lines_frame`; the files are small (~265k lines total).
- **`parse_file_name` returns split `"rul"`** for `RUL_FD00x.txt` so the three file kinds
  stay distinct; bronze only accepts `train|test`.
- **Bad input fails the query, not silently**: an unknown file name or a line without 26
  fields raises a Spark error (`raise_error`) naming the file/line when the data is read.
- **`to_datasets` returns all four subsets**, with 0 engines for a subset absent from the
  data, so the table always has 4 rows.
- Lesson written to `docs/learn/lessons/T-004.md` (required by `/build` although `docs/`
  is on the must-not-change list, as T-001 did). Glossary left alone for the manager:
  suggested entry **Window function**.
- A test RUL with no matching `RUL_` line gives `rul` null (not an error).
