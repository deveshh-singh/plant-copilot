# Graduation checklist: "Do I own my project?"

<!-- Used by /learn check. A box is ticked only when the owner SHOWS it (says it in
their own words, or does it with Claude watching), never because Claude explained
it. The ticks and dates are kept in docs/learn/PROFILE.md. A finished project should
reach 10 / 10; that is what "the owner knows their project" means here. -->

1. **Explain it.** Describe what the project does and its main parts, and draw the
   picture in `how-it-works.md` from memory, roughly.
2. **Follow one thing through.** Walk one real journey (a click, a pipeline run)
   from start to end, naming the files.
3. **Run it.** Start it on your computer (or trigger a dev run) and see it work.
4. **Test it.** Run the tests, and say what a pass and a failure look like.
5. **Change it.** Make a small change yourself (a text, a colour, a threshold),
   see the effect, and undo it.
6. **Read an error.** Given an error message, find the file and line it points to
   and say in plain words what it means.
7. **Ship it.** Say how a change goes live, and do it once with Claude watching.
8. **Undo it.** Use git to see recent changes and go back to an earlier version.
9. **Keep it safe.** Say where the secrets are, what costs money, and which
   accounts you own.
10. **Ask well.** Write a bug report or a feature request Claude can act on
    without follow-up questions (what happened, what you expected, how to see it).
